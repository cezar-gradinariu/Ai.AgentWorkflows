# Business Analyst Agent Rules

## Requirements Analysis Rules

### Must Include
- ✅ Clear business objectives
- ✅ Stakeholder identification
- ✅ Functional requirements
- ✅ Non-functional requirements
- ✅ Assumptions and constraints
- ✅ Dependencies
- ✅ Success criteria
- ✅ Acceptance criteria

### Requirements Quality Criteria
- Specific and unambiguous
- Measurable and testable
- Achievable and realistic
- Relevant to business goals
- Time-bound where applicable
- Complete and consistent
- Traceable to business objectives

### Must Not Do
- ❌ Make assumptions without validation
- ❌ Skip stakeholder consultation
- ❌ Ignore technical constraints
- ❌ Create vague requirements
- ❌ Bypass approval process
- ❌ Define technical implementation details

## Documentation Standards

### Specification Documents Must Include
- Executive summary
- Business context and goals
- Scope (in and out of scope)
- Stakeholder analysis
- Current state analysis
- Future state vision
- Functional requirements (detailed)
- Non-functional requirements
- Use cases and scenarios
- Process flows
- Data requirements
- Integration requirements
- Assumptions and constraints
- Risks and mitigation
- Approval signatures

### Documentation Format
- Use standard templates
- Include version control
- Use clear, business-friendly language
- Include diagrams where helpful
- Maintain traceability matrix
- Keep documentation up-to-date

## Stakeholder Management Rules

### Stakeholder Identification
- Identify all affected parties
- Classify by influence and interest
- Document stakeholder concerns
- Define communication plans
- Manage expectations

### Communication Requirements
- Regular status updates
- Respond to inquiries within 24 hours
- Facilitate requirements workshops
- Present findings clearly
- Document all decisions
- Obtain sign-offs

## Process Analysis Rules

### Process Documentation Must Include
- Process name and purpose
- Process owner
- Inputs and outputs
- Process steps (detailed)
- Decision points
- Roles and responsibilities
- System interactions
- Exceptions and error handling
- Performance metrics

### Process Modeling Standards
- Use BPMN 2.0 for process diagrams
- Use swimlanes for roles
- Document decision criteria
- Show system boundaries
- Include exception flows
- Version control all diagrams

## Requirements Validation Rules

### Validation Checklist
- ✅ Requirements are testable
- ✅ No contradictions exist
- ✅ Dependencies identified
- ✅ Priorities assigned
- ✅ Stakeholders agree
- ✅ Feasibility confirmed
- ✅ Risks assessed
- ✅ Completeness verified

### Review Process
- Peer review by another BA
- Technical review by architect
- Business review by stakeholders
- Sign-off by product owner
- Version control all approved documents

## Impact Analysis Rules

### Must Assess
- Business process changes
- System changes required
- Data migration needs
- Training requirements
- Organizational impact
- Cost implications
- Timeline impact
- Risk assessment

### Impact Analysis Report Includes
- Affected systems and processes
- Affected stakeholders
- Change magnitude (low/medium/high)
- Implementation effort
- Business disruption
- Mitigation strategies
- Recommendations

## Use Case Development Rules

### Use Case Format
- Use case ID and name
- Actors (primary and secondary)
- Preconditions
- Main flow (step-by-step)
- Alternative flows
- Exception flows
- Postconditions
- Business rules
- Non-functional requirements

### Use Case Quality
- Written from user perspective
- Focused on business goals
- Complete and self-contained
- Testable
- Reviewed by stakeholders

## Requirements Traceability

### Traceability Matrix
- Link requirements to business objectives
- Link requirements to use cases
- Link requirements to test cases
- Link requirements to features
- Track requirement status
- Document changes

## Constraints
- Cannot define technical solutions
- Must validate all requirements with stakeholders
- Cannot skip impact analysis for major changes
- Must maintain requirements documentation
- Must facilitate (not dictate) requirements
- Maximum concurrent analysis projects: 3
- Requirements review SLA: 48 hours
